## 面向用户的变化

| 范围 | 建议写入中英文发行说明的内容 |
| --- | --- |
| 多设备投屏 | 合并布局保留各设备的实时画面、输入和工具栏。拆分时保留会话，修复 macOS 窗口反复抢焦点的问题。同系统多台设备可通过设备名和型号区分。 |
| Android | 提供应用、截图、Shell、Logcat、进程、布局和 WebView 七项工作区工具。支持拖入 APK 安装，投屏工具栏可返回、回主界面和调节音量。普通 Tab 发送给手机，Shift+Tab 可聚焦本栏工具。改善多用户设备归属和取消操作后的 USB 连接清理。 |
| USB iPhone | 改善 WDA 和 ReplayKit 连接恢复。部分设备通过普通 USB 挂载开发者镜像时要求 RSD，现在可以在启动 Runner 的同一条隧道内完成挂载。 |
| CLI / MCP | 客户端从 35 项操作扩展到 40 项，覆盖独立截图、前台 WebView 和窗口布局／聚焦；安装示例使用本版 tgz。 |

增量来自 [#104](https://github.com/MonsterXia/scrcpy-plus/pull/104)、[#105](https://github.com/MonsterXia/scrcpy-plus/pull/105) 和 [#106](https://github.com/MonsterXia/scrcpy-plus/pull/106)。[#103](https://github.com/MonsterXia/scrcpy-plus/pull/103) 归档了上一版发布证据。

## 执行与验收

- [x] **准备版本 PR。** 执行时重查远端 master、标签及 Release（含草稿）。若功能基线有新提交，先核对新增差异。将 `package.json` 与 `package-lock.json` 的两个根版本字段同步到 `1.0.5-dev.4`。更新 `README.md`、`README_ZH.md`、`docs/scrcpy-plus/automation/README.md` 和 `RUNBOOK.md`，编写 `docs/releases/1.0.5-dev.4.md` 候选说明；公开后再更新下载入口。
- [x] **验证候选提交。** 执行 `npm test`、`npm run lint`、iOS 助手 Python 测试、双语 Electron 投屏回归和 `npm run build:cli && npm run check:automation-package`。重点检查多设备输入归属、拆分后会话连续、断连后工具栏焦点，以及安装的 CLI schema 与 MCP 的 40 项操作一致。对最终 PR 提交完成独立复审，确认 test、lint、windows-package、macos-package-arm64 及其 WDA 依赖成功后合入。
- [x] **构建发行安装包。** 在受保护的 master 手动执行 `gh workflow run build.yml --ref master`。记录 run ID，核对 `headSha` 等于准备 PR 合并 SHA。等待 release-source、ios-wda / wda、windows-release、macos-release 成功。Windows 核对安装启动及 Authenticode 实际状态；Mac 核对 Developer ID、app 与 DMG 公证和票据、Gatekeeper 及安装启动。[Release Build](../../../.github/workflows/build.yml)
- [x] **校验附件。** 在 dev.4 专用临时目录下载该 run 的 `windows-release-x64` 和 `macos-release-arm64`。旧发布工具提交 `36f7b2c` 的下载和清单脚本写死 dev.3，复用前适配版本、路径和更新源预期，并记录工具 SHA。核对 artifact ID、ZIP 摘要、报告内的源 SHA、架构和版本。按 YAML 中的文件名配对安装包和 blockmap，校验最终安装包大小、SHA-512、附件 SHA-256，并从实际下载的 tgz 隔离安装验证 40 项操作。按现流程预计 12 项附件：两个安装包、两个 blockmap、两个更新 YAML、三个验证报告、CLI tgz、`SHA256SUMS.txt`、`release-validation.json`。
- [x] **公开预发布。** 发布前用生产 ReleaseProvider 验证两平台目前仍分别选到稳定版 1.0.4 和 Beta 版 dev.3。将新标签指向已校验的构建 SHA，创建 prerelease 草稿，以 Release ID 上传附件并全部重新下载比对。确认清单、双语说明和下载链接一致，再以 `prerelease=true`、`make_latest=false` 公开。构建 SHA、附件字节或目标 Release ID 不一致时停在公开前；再次执行时按原 run、标签和草稿 ID 核对。
- [x] **验证公开结果并归档。** 回读公开 Release 的 ID、标签提交、附件 ID 与摘要，确认稳定 Latest 为 `v1.0.4`。在 Windows x64 和 macOS arm64 的提供器场景分别验证下表，保存报告。将构建链接、安装包摘要、签名结果、附件清单和线上结果写入 `docs/releases/1.0.5-dev.4-evidence.json`，通过归档 PR 更新发行记录和 RUNBOOK。[生产更新源检查脚本](../../../script/check-release-source.mjs)
